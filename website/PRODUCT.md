# TypeCV website product contract

The website presents TypeCV as a general computer vision library implemented in TypeScript and built on TypeShade. SfM is one area within the broader CV scope. Current public browser functionality consists of compiled CPU/WebGPU two-view geometric verification and local video SfM with TypeShade GPU feature extraction, matching, incremental reconstruction, and Three.js visualization.

The synthetic playground constructs a known two-view scene and calls the library implementation selected by the user. It reports the actual inlier, pose-quality, and backend execution results. It does not silently fall back from WebGPU to CPU.

The video lab demuxes local files with Mediabunny and decodes every presentation frame in order using supported browser codecs. One analysis frame is in flight; GPU backpressure waits rather than dropping frames. There is no FPS sampling or total-frame ceiling. The analysis image has a 640-pixel long edge. The source video seeks to each actual timestamp while processing. This is sequential whole-video analysis; measured throughput can be slower than playback. Unsupported codecs report an error and can use prepared frame JSON.

The frame-stage display follows actual feature, matching, geometry and depth events. Gray detections and orange candidate correspondences are replaced by camera-space depth colors only for real triangulated observations. Depth uses optical-axis z, with near red and far blue, a per-frame robust range legend, and relative units. The Three.js point cloud samples RGB from actual observed image pixels. Selecting a point links its real observation to the 3D point. A calibrated image plane, camera forward arrow, consecutive-frame translation arrow, rotation/translation readout, and full frame timeline explain the reconstruction. Missing poses are never interpolated. Trajectory replay re-decodes the original selected frame. While a run is busy the 3D view shows what each new map changed (new points and cameras glow, moved ones slide to their reported place, dropped points fade out in red), pulses the cameras the current stage works on, shows the frame being analysed, and says how long ago the worker last reported (`docs/lab-live-view.md`).

IncrementalSfmSession bounds local reconstruction to 32 cameras by default (configurable 8–64), preserves world coordinates when moving its fixed anchors, and archives all registered cameras, point identities and observations. Historical output grows with the video. Final shared-focal refinement applies to the active local window, not the entire historical trajectory. The renderer and orbit controls persist between snapshots. JSON exports retain point IDs, source RGB and observations; PLY uses observed RGB.

An attributed eight-frame Pexels pyramid sequence and prepared frame JSON remain available for reproducible real-footage runs, using the same sequential worker/session path. Intrinsics remain assumed; the sample has no ground-truth camera poses or metric scale. Unregistered views retain their reasons, and final JSON/PLY exports remain available. Loop closure, relocalization, dense surfaces and physical-camera-rate guarantees are outside the implemented scope.

The website uses the Astro, React, Ant Design and Tailwind template described in `references/typenn/PRODUCT.md`. Deployment is public through Cloudflare Workers Static Assets on `cv.typeshade.dev`. The existing organization Actions secret `CLOUDFLARE_API_TOKEN` supplies deployment authorization.
